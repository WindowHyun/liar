# Electron 버전

프로그램을 켜면 같은 네트워크의 다른 참가자를 **자동으로 찾아 한 방에 모인다.**
주소를 입력하거나 누가 서버를 켤지 정할 필요가 없다.

```bash
npm install
npm run electron
```

**포트 55500** 하나만 쓴다. UDP 55500으로 서로를 찾고, 뽑힌 한 명이 TCP 55500에 게임
서버를 켠다. 처음 실행할 때 방화벽 허용 팝업이 뜨면 반드시 "허용"을 눌러야 한다.

## 구조

```
   각 PC의 Electron 인스턴스
   ────────────────────────
   UDP 55500 (브로드캐스트)  ← 서로를 찾는 용도로만. 게임 규칙은 여기로 안 다닌다.
        │
        └─ 호스트 선출 ─→ 뽑힌 한 명만 TCP 55500에 게임 서버를 켠다
                             │
   나머지는 그 서버에 WebSocket으로 붙는다 ─┘  ← 게임은 전부 여기서
```

UDP는 "누가 있는지" 찾는 데만 쓴다. 그래서 LAN 버전에서 필요했던 수신 중복 제거,
ACK/재전송, 라운드 호스트 조정이 하나도 필요 없다. 알림(announce)은 여러 번 도착해도
"마지막으로 본 시각"을 갱신할 뿐이라 중복이 무해하다.

## 호스트를 어떻게 정하는가

시계를 쓰지 않는다. PC마다 시계가 어긋나 있으면 엉뚱한 사람이 계속 뽑히기 때문이다.

1. **호스트라고 알리는 인스턴스가 있으면** → 그중 nodeId가 가장 작은 쪽
2. **아무도 호스트가 아니면** → 살아 있는 인스턴스 중 nodeId가 가장 작은 쪽

1번이 먼저라서 나중에 들어온 사람이 nodeId가 더 작아도 판을 뺏지 않는다. 호스트가
나가면 그때 2번이 걸려 다음 사람이 이어받고, 모두가 같은 규칙으로 같은 답을 낸다.

시작 직후 2.5초는 선출을 미룬다. 이미 돌고 있는 판이 있는데 그 알림을 아직 못 들은
상태에서 "아무도 호스트가 아니네"라고 판단하면 호스트가 둘이 되기 때문이다.

### 호스트가 바뀌면

화면은 새 호스트 주소로 알아서 다시 붙는다(창을 다시 열 필요 없다).
다만 **진행 중이던 라운드는 초기화된다.** 라운드 상태가 옛 호스트의 메모리에만 있었기
때문이다. 이걸 살리려면 상태 복제가 필요한데, 파티 게임에는 과한 복잡도라 하지 않았다.

## 사내 프록시 주의

이 앱은 바깥 인터넷에 나갈 일이 전혀 없다. 그런데 회사 PC처럼 시스템 프록시가 걸려
있으면 Chromium이 LAN 주소까지 프록시로 보내고, 프록시가 이를 거절한다.

```
WebSocket connection to 'ws://192.168.0.5:55500/' failed:
Error during WebSocket handshake: Unexpected response code: 403
```

증상이 고약하다. **루프백(내 화면)은 프록시를 안 타므로 나는 잘 되는데, 남에게는 안
붙는다.** 그래서 `main.js`에서 `session.setProxy({ mode: 'direct' })`로 프록시를 아예
타지 않도록 못 박아 두었다. 이 줄을 지우면 프록시가 걸린 PC에서 재발한다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `main.js` | 창을 띄우고 peer와 이어 준다. 게임 규칙은 없다 |
| `peer.js` | 발견 + 호스트 선출 + 게임 서버 켜고 끄기. **Electron을 모른다** |
| `discovery.js` | UDP 55500 알림/수신 |
| `ui-server.js` | 화면 파일용 로컬 전용 HTTP (127.0.0.1) |
| `preload.js` | 화면에 "붙을 서버 주소"만 노출 |

게임 규칙은 `web/room.js`, 서버는 `web/game-server.js`로 웹 버전과 **같은 것**을 쓴다.
`peer.js`가 Electron을 모르는 덕분에, 테스트에서 `node`로 인스턴스를 여러 개 띄워
발견·선출·인계를 그대로 확인할 수 있다.

### 화면을 file:// 로 띄우지 않는 이유

`file://` 은 출처가 없는 페이지라 다른 PC의 WebSocket으로 붙는 것이 막힐 수 있다.
`ui-server.js`가 `http://127.0.0.1:<임의포트>` 로 내려주면 일반 웹페이지와 같은 취급을
받아 그 제약이 없다. 바깥에서는 보이지 않는다(127.0.0.1에만 바인딩).

## 테스트

```bash
node test/discovery-test.js   # 실제 프로세스 4개로 발견·선출·인계 (전용 포트 55599)
node test/bridge-test.js      # 호스트가 바뀌면 화면이 새 주소로 다시 붙는지
```

`discovery-test.js`는 실행 중인 앱(55500)을 4번째 참가자로 잡지 않도록 55599를 쓴다.

## 같은 PC에서 두 번 실행

막지 않았다. 게임 통신이 TCP라서 LAN 버전처럼 "제시어가 한쪽에만 도착하는" 문제가
생기지 않고, 한 PC에서 둘을 띄워 시험해 보기 편하다.

단, 창 두 개가 저장소를 공유하면 토큰이 같아져 한 참가자로 합쳐질 수 있다. 그래서
서버는 **이미 접속 중인 자리는 토큰이 같아도 새 참가자로** 받는다.

## 배포(exe)로 만들 때

`electron-builder` 등을 붙이면 된다. 이 저장소에는 넣지 않았다.
`package.json`의 `main`이 `electron/main.js`를 가리키고 있으므로 그대로 패키징하면 된다.
