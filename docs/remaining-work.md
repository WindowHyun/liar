## 1. 지금 고쳐야 하는 것

### W-1. 라운드 중에 전원이 나가면 방이 영구히 잠긴다 **[실측] — 최우선**

`web/room.js`의 `disconnect()`는 로비/결과 화면일 때만 참가자를 목록에서 지운다.
라운드 진행 중에는 자리를 남겨 두는데(돌아올 수 있으니까), **아무도 돌아오지 않으면
아무것도 그 상태를 풀어 주지 않는다.**

재현:

```
시작 후 phase: playing
전원 퇴장 후 phase: playing          ← 라운드가 그대로 남는다
새로 들어온 사람이 보는 것 → phase: playing / canStart: false / inRound: false
새 참가자가 시작 시도: 이미 게임이 진행 중입니다.
참가자 목록에 남은 유령: A(끊김), B(끊김), C(끊김), 새참가자
```

이후 들어오는 사람은 **영원히 관전자**가 되고 게임을 시작할 수 없다. 서버를 다시 켜야
풀린다. 웹 버전에서는 서버가 계속 떠 있으므로 치명적이고, Electron 버전에서는 호스트가
바뀌면 새 방이 생겨 우회되지만 호스트가 그대로 남아 있으면 똑같이 잠긴다.

고칠 방향: 접속자가 0명이 되면 라운드를 취소하고 로비로 되돌린다. 겸사겸사 끊긴 지 오래된
참가자는 라운드 중이라도 정리한다.

### W-2. 찬반 중 전원이 나가면 0명인데 투표로 넘어간다 **[실측]**

`settleProposal()`의 통과 조건이 `찬성 * 2 >= 전체`인데, 전체가 0이면 `0 >= 0`이라 참이 된다.

```
찬반 시작: proposal
찬반 중 전원 퇴장 → voting   (0명인데 50% 조건이 통과됨)
```

투표 제한 시간 30초가 지나면 `noVotes`로 정리되므로 완전히 멈추지는 않지만, 0명짜리
투표가 30초 동안 떠 있는 건 명백히 의도가 아니다. W-1을 고치면 대부분 같이 사라지지만,
`전체 > 0` 조건은 따로 넣어 두는 편이 안전하다.

### W-3. 관전자가 진행 중인 판에 끼어들어 대화할 수 있다 **[실측]**

라운드 도중에 들어온 사람은 관전자가 되지만 `say()`는 `players`에 있기만 하면 통과시킨다.

```
관전자가 채팅 시도: 가능(진행 중인 판에 끼어들 수 있음)
```

관전자는 제시어를 모르므로 정보가 새지는 않는다. 다만 판을 흐릴 수 있고, 화면상 참가자와
구분 없이 말풍선이 뜬다. 관전자 발언을 막거나, 최소한 "관전"이라고 표시해야 한다.

## 2. 결정이 필요한 것 (기술 문제가 아니라 선택)

### D-1. 세 구현 중 무엇을 남길 것인가

지금 한 저장소에 게임이 세 벌 있다. 규칙도 두 벌이다(`game.js`와 `web/room.js`).
제시어 목록도 두 벌이다(`game.js`의 `WORD_LIST`, `web/words.js` — 각 30개, 내용 동일).

- **LAN 버전을 지운다면**: `network.js` `game.js` `public.js` `server.js` `protocol.js`와
  테스트 4개(`transport-test` `round-test` `server-test` `ui-test`, 56건)가 함께 빠진다.
  저장소가 절반으로 줄고 유지보수 대상이 하나가 된다.
- **남긴다면**: 웹/Electron이 못 쓰는 환경(서버를 못 켜는 상황)에 대한 대안이 된다.
  대신 규칙을 고칠 때마다 두 곳을 고쳐야 한다.

지금은 "웹/Electron이 상위 호환"이라 LAN 버전을 남길 실익이 잘 보이지 않는다.
**결정만 해 주면 정리는 금방이다.**

### D-2. `package.json`의 진입점이 옛 버전을 가리킨다 **[코드]**

```json
"main": "electron/main.js",
"scripts": { "start": "node server.js", "web": "node web/server.js", "electron": "electron ." }
```

`npm start`가 **LAN 버전**을 띄운다. D-1의 결정에 따라 `start`를 `electron` 또는 `web`으로
바꿔야 한다. 지금은 아무것도 모르는 사람이 `npm start`를 치면 가장 오래된 버전이 뜬다.

### D-3. 방을 나눌 것인가 **[설계]**

지금은 방이 하나다. 웹 버전은 서버 주소가 곧 방이라 서버를 두 개 띄우면 되지만,
Electron 버전은 **같은 LAN이면 무조건 한 방**이다. 사무실에서 두 팀이 동시에 하려면
방 코드가 필요하다. 없어도 되는지 확인이 필요하다.

## 3. Electron 버전에서 아직 안 한 것

### E-1. 호스트가 바뀌면 진행 중이던 라운드가 사라진다 **[설계]**

라운드 상태가 옛 호스트의 메모리에만 있어서다. 화면은 새 호스트로 알아서 다시 붙지만
게임은 처음부터다. 살리려면 상태 복제가 필요한데 파티 게임에는 과한 복잡도라 하지 않았다.
**받아들일지 결정만 하면 된다.** 최소한 "호스트가 바뀌어 라운드가 초기화되었습니다"라고
화면에 알려 주는 것은 지금도 없다.

### E-2. 발견 메시지에 버전을 실어 보내면서 검사하지 않는다 **[코드]**

`electron/discovery.js:108`이 `{ v: 1, nodeId, isHost }`를 보내지만, 받는 쪽은 `msg.v`를
읽지 않는다. 지금은 필드만 있고 아무 일도 하지 않는다.

배포 시점이 갈려 구/신 버전이 섞이면 서로를 발견해 한 방에 모이려 하고, 게임 메시지 형식이
다르면 그때 가서 이상하게 깨진다. LAN 버전에서 `PROTOCOL_VERSION`으로 잡아 두었던 문제가
Electron 버전에는 없다. `v`가 다르면 무시하고 사용자에게 알리는 처리가 필요하다.

### E-3. 발견 프로토콜에 인증이 없다 **[코드]**

같은 LAN의 누구나 announce를 보낼 수 있고, `nodeId`를 작게 만들면 호스트를 가져갈 수 있다.
호스트가 되면 라이어와 제시어를 정하므로 판 전체를 좌우한다.

사내 파티 게임이라면 감수할 수 있는 위험이지만, **의도한 선택인지 문서에 명시**해 둘 필요가
있다. 막으려면 공유 비밀번호로 announce에 서명하는 정도면 충분하다.

### E-4. CSP가 없다 **[실측 - Electron 콘솔 경고]**

```
Electron Security Warning (Insecure Content-Security-Policy)
This renderer process has either no Content Security Policy set...
```

지금 화면은 로컬 파일만 불러오므로 실제 위험은 낮다. 다만 경고가 콘솔에 계속 뜨고,
나중에 외부 리소스를 쓰게 되면 그때는 진짜 문제가 된다.

### E-5. macOS 창 닫기 관례를 따르지 않는다 **[코드]**

`electron/main.js:106`의 `window-all-closed`가 플랫폼 구분 없이 `app.quit()`을 부른다.
macOS는 창을 닫아도 앱이 살아 있는 것이 관례다(Dock에서 다시 열 수 있어야 한다).
Windows만 쓸 거라면 그대로 둬도 된다.

### E-6. 앱을 다시 켜면 닉네임을 다시 입력해야 한다 **[코드]**

화면 서버(`electron/ui-server.js`)가 매번 **빈 포트를 새로 잡기 때문에**(`listen(0)`),
출처가 `http://127.0.0.1:33329` → `http://127.0.0.1:39343`처럼 바뀐다. `localStorage`는
출처마다 따로라서 저장해 둔 닉네임과 토큰을 못 읽는다.

세션 안에서는 문제없다(새로고침·호스트 인계 시 유지). 앱 재시작 때만 잃는다.
고정 포트를 쓰되 충돌하면 다음 번호로 넘어가는 방식이면 해결된다.

### E-7. 배포용 패키징 설정이 없다 **[설계]**

`electron-builder` 설정, 앱 아이콘, 서명, 자동 업데이트가 전부 없다. exe로 만들려면 필요하다.
`main`이 `electron/main.js`를 가리키고 있으므로 빌더만 붙이면 되는 상태다.

## 5. LAN 버전에 그대로 남아 있는 것

D-1에서 "남긴다"로 정하면 아래도 남는다.

- **P3-32 위조 방지 없음** — LAN의 누구나 `START`/`RESULT`/`VOTE`를 위조할 수 있다.
  라운드 시작 시 호스트가 만든 공유 시크릿으로 HMAC을 붙이면 막히지만, `START` 자체는
  여전히 인증되지 않아 효과가 제한적이다. 신뢰 모델을 정하는 결정이 먼저다.
- **P3-37 모듈 분리 부분만 됨** — `protocol.js`만 떼어냈고, `network.js`는 여전히 전송과
  프리젠스(피어 목록·버전 검사)를 함께 들고 있다.
- **호스트가 정답을 안다** — 시작 버튼을 누른 사람이 자기 PC에서 라이어와 제시어를 뽑는다.
  구조적 한계다. **웹/Electron 버전에는 없는 문제**이므로, D-1에서 LAN 버전을 지우면
  이 항목도 함께 사라진다.
