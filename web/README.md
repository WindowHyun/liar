# 웹 버전 (프로토타입)

한 사람만 서버를 켜고, 나머지는 브라우저로 접속한다.

```bash
npm install
npm run web          # 포트 4100. PORT=4200 npm run web 으로 바꿀 수 있다
```

띄우면 접속 주소가 찍힌다. 같은 네트워크에 있는 사람에게 `http://<내IP>:4100` 을 알려주면 된다.
최소 3명.

## LAN(UDP) 버전과 무엇이 다른가

| | LAN 버전 (저장소 루트) | 웹 버전 (`web/`) |
|---|---|---|
| 실행 | 참가자 각자가 자기 PC에서 실행 | 한 사람만 서버를 켠다 |
| 통신 | UDP 브로드캐스트 P2P | WebSocket, 서버 경유 |
| 판정 주체 | 라운드 호스트(참가자 중 한 명) | 서버 |
| 제시어를 아는 곳 | 시작 버튼을 누른 사람의 PC | 서버만 |

## 이 구조가 없애 버리는 문제들

LAN 버전에서 손이 많이 갔던 것들은 대부분 "판정하는 주체가 여럿"이라서 생겼다.
서버가 유일한 권위가 되면 아래 층이 통째로 필요 없어진다.

- **수신 중복 제거(msgId), ACK/재전송** — TCP가 해 준다
- **라운드 호스트 선출, `roundId`, 호스트 이탈 시 라운드 취소, 동시 시작 조정** — 서버가 곧 권위
- **REVEAL 왕복** — 지목된 사람이 정체를 알려 줄 필요가 없다. 서버가 이미 안다
- **프로토콜 버전 불일치** — 화면은 서버가 내려주므로 버전이 갈릴 수 없다
- **2중 실행 시 제시어가 한쪽에만 도착** — 유니캐스트 자체가 없다
- **호스트가 정답을 아는 문제** — 제시어는 서버만 알고, 라이어에게는 전송되지 않는다

## 지켜야 할 원칙 하나

**상태가 바뀌면 "각자에게 맞춘 전체 상태"를 통째로 다시 보낸다.** 증분 이벤트를 쌓아
화면을 맞추지 않는다. LAN 버전에서 화면이 어긋나던 원인이 그거였고, 인원이 10명 남짓인
이 게임에서는 전체 전송이 훨씬 싸다. 메시지를 몇 개 놓쳐도 다음 상태 한 번이면 정확히
복구된다. 인원이 크게 늘면 그때 증분으로 바꾸면 된다.

## 파일

- `server.js` — HTTP + WebSocket 연결 처리. 규칙은 들고 있지 않다
- `room.js` — 규칙과 상태 전부. I/O가 없어 테스트하기 쉽다
- `protocol.js` — 브라우저가 보내는 요청 6가지 검증
- `words.js` — 제시어 목록
- `public/` — 브라우저에 그대로 내려가는 정적 파일

## 테스트

```bash
node test/web-room-test.js   # 규칙 26건 (가상 시계로 30초 대기 없이)
node test/web-ui-test.js     # 실제 Chromium 창 3개로 한 판 끝까지 13건
```

`web-ui-test.js`는 Playwright가 없으면 건너뛴다.

## Electron으로 넘어갈 때

이 구조 그대로 감싸면 된다.

1. Electron 메인 프로세스에서 `web/server.js`를 그대로 띄운다(포트는 그대로).
2. `BrowserWindow`로 `http://localhost:4100` 을 연다.
3. 다른 참가자는 여전히 브라우저로 들어오거나, 같은 exe를 받아 각자 창을 띄운다.

`web/` 아래 코드는 Electron을 전혀 모르는 상태로 두는 게 좋다. 그래야 브라우저로도
계속 돌아가고, 문제가 생겼을 때 Electron 문제인지 게임 문제인지 바로 갈린다.

## 아직 안 한 것

- **방 나누기** — 지금은 방이 하나다. 접속한 사람은 모두 같은 게임에 들어간다
- **접속 제한** — 주소를 아는 사람은 누구나 들어온다. 사내 LAN 전제
- **HTTPS** — 평문 WebSocket이다. 같은 네트워크 밖으로 낼 거라면 필요하다
